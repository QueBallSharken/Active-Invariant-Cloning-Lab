# Glossary

Version: 0.1

Status: Active

Repository: Active Invariant Cloning Lab

---

# Purpose

This glossary defines repository terminology used throughout the Active Invariant Cloning (AIC) project.

Definitions may evolve as evidence is collected.

Changes should be documented.

Repository artifacts remain authoritative.

---

# Active Invariant Cloning (AIC)

The research effort investigating whether a governing invariant can be replicated into multiple active instances while preserving:

- Semantic equivalence
- Governance authority
- Refusal capability
- Survivability

across mutation-capable paths.

---

# Invariant

A governing constraint that defines:

- Permitted behavior
- Prohibited behavior
- Required behavior
- Enforceable conditions

An invariant governs mutation behavior.

---

# Clone

An active governance instance derived from an originating invariant.

A clone participates in governance.

A clone is not merely documentation, evidence, or historical approval.

---

# Origin Invariant

The invariant from which one or more clones are derived.

The origin invariant serves as the semantic reference point for comparison.

---

# Live

A property indicating that a clone actively participates in governance activities during execution.

A live clone influences mutation evaluation.

---

# Binding

A property indicating that a mutation cannot proceed while violating the governing clone.

Binding implies enforceable governance participation.

---

# Refusal-Capable

A property indicating that a clone retains the ability to prevent a mutation.

Detection alone is insufficient.

Observation alone is insufficient.

The clone must retain governance influence.

---

# Semantic Equivalence

The condition in which two or more clones preserve the same governing meaning despite differences in:

- Representation
- Encoding
- Transport
- Environment
- Implementation

Semantic equivalence concerns meaning rather than form.

---

# Semantic Drift

A change in governing meaning that alters governance behavior.

Semantic drift represents loss of semantic equivalence.

---

# Structural Drift

A change in representation that does not necessarily alter governing meaning.

Structural drift does not automatically imply semantic drift.

---

# Behavioral Drift

A divergence in governance outcomes when equivalent mutations are evaluated.

Behavioral drift may indicate semantic drift.

---

# Authority Drift

Unexpected change in governance authority.

Examples include:

- Authority loss
- Authority expansion
- Unauthorized delegation
- Refusal loss

---

# Environmental Drift

Divergence caused by differences in execution conditions.

Examples include:

- Platform differences
- Runtime differences
- Dependency differences
- Configuration differences

---

# Clone Agreement

The condition in which multiple clones produce equivalent governance outcomes when evaluating equivalent mutations.

Agreement is evidence.

Agreement is not proof.

---

# Clone Disagreement

The condition in which multiple clones produce different governance outcomes when evaluating equivalent mutations.

Disagreement may indicate:

- Drift
- Translation failure
- Hidden mutation paths
- Governance failure
- Unauthorized modification

---

# Clone Survivability

The ability of a clone to remain:

- Live
- Binding
- Refusal-Capable
- Semantically Equivalent

throughout participation in governance activities.

---

# Governed Execution

Execution in which mutations remain subject to active clone participation before becoming irreversible.

Governed execution requires active governance influence.

---

# Governance Failure

A condition in which execution proceeds despite governance requirements not being satisfied.

Examples include:

- Clone bypass
- Refusal bypass
- Authority bypass
- Hidden mutation paths

---

# Mutation

A state transition that changes governed system behavior, state, authority, configuration, execution outcome, or persistence state.

Mutation definitions may be refined through experimentation.

---

# Mutation Path

The sequence of boundaries, decisions, transformations, and execution steps through which a mutation travels.

---

# Mutation-Capable Boundary

A boundary capable of influencing, transforming, authorizing, modifying, executing, or finalizing a mutation.

---

# Evidence

Information produced through implementation, experimentation, testing, measurement, or verification.

Evidence outranks assumptions.

---

# Verification

The process of determining whether a claim is supported by reproducible evidence.

---

# Research Artifact

A repository artifact used to explore, document, test, or analyze a claim.

Research artifacts are not automatically validated.

---

# Repository Principle

Evidence before belief.

Implementation before speculation.

Verification before conclusion.

Continuity before convenience.

---

# Final Statement

Definitions exist to improve clarity.

Evidence determines whether repository claims survive testing.
